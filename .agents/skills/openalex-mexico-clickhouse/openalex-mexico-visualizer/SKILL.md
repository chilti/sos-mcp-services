# OpenAlex Mexico Visualizer

> **Language Rule:** Respond and label outputs in the user's language (default to English for script plots/labels, or pass `--lang es` when the user interacts in Spanish).

Presentation layer and interactive visual artifact generation engine for Mexican scientific production.

## Overview

Transforms JSON analytical results generated by the data skills (`openalex-mexico-aggregations`, `openalex-mexico-semantic-search`, `openalex-mexico-works-search`, etc.) into:
1. **Horizontal Bar Charts (`top-ranking`):** Institutional or author capacity ranking colored by FWCI with a detailed table and affiliation badges.
2. **Dual Time Series (`timeseries`):** Annual publications combined with the chronological evolution of FWCI relative to the world benchmark (1.00).
3. **Open Access Donuts (`oa-donut`):** Distribution across the 6 OA routes (Diamond vs. Commercial) and APC expenditure quantification.
4. **Hierarchical Taxonomic Sunburst (`sunburst`):** Multi-level concentric chart (Domain → Field → Subfield → Topic) with interactive zoom.
5. **Official 17 SDGs Matrix (`sdg-grid`):** Grid featuring the official UN color palette and comparative table.
6. **Publications Dossier (`dossier-works`):** Publication catalogs with domestic vs. international co-authorship breakdown.
7. **Static PNG Cards:** Compact 200 DPI charts ready to be embedded directly in chat.

## Dependencies

- **Python Environment:** Python 3.10+ (`clickhouse-connect`)
- **CLI Script:** `scripts/openalex_visualizer_cli.py`
- **Core Libraries:** `plotly`, `matplotlib`, `pyvis`

## ⚠️ NO-RECYCLING RULE AND MANDATORY 2-PHASE WORKFLOW

> [!CAUTION]
> ### 1. Strict Prohibition of Reusing Foreign Files
> **NEVER search for or link files generated in parent directories or previous sessions (`../<hash>/`).**
> If the user asks *"show the sunburst"*, *"plot the ranking"*, or *"make an OA donut"*:
> * **DO NOT assume the file already exists.**
> * **DO NOT use grep across sibling folders.**
> * If you attempt to link an external file, the OpenHands Canvas viewer will fail, showing a black screen or raw text.

> [!IMPORTANT]
> ### 2. Mandatory Two-Phase Workflow
> * **Phase 1 (Quantitative Computation):** Run the appropriate analytical skill (`openalex-mexico-aggregations` or `openalex-mexico-works-search`) and generate the JSON file in `./data/<name>.json` inside the current workspace.
> * **Phase 2 (Rendering):** Invoke `openalex_visualizer_cli.py` with that JSON (passing `--lang es` if the user interacts in Spanish, or default `--lang en`) to produce the interactive `.html` and `.png` card in `./reports/`.
> * **Phase 3 (Presentation):** Invoke `canvas_ui_control` passing the local path `./reports/<name>.png`.

### 1. Automatic Generation (Smart Detection)
The visualizer detects the internal structure of the JSON (`top_entities`, `grouped_by`, `works`, etc.) and renders the corresponding artifact:
```bash
python scripts/openalex_visualizer_cli.py \
  --input ./data/datos.json \
  --title "Scientometric Analysis of Lithium in Mexico" \
  --lang en \
  --output ./reports/artefacto_interactivo.html \
  --png ./reports/tarjeta_chat.png
```

### 2. Force a Specific Visualization Type
Available types (`--type`):
- `top-ranking`: **Horizontal bar chart** for institutional or researcher rankings ordered by publications and colored by FWCI.
- `sunburst`: For multi-level hierarchical taxonomic structures (Domain → Field → Subfield → Topic) in specific themes (lithium, AI, etc.).
- `sdg-grid`: **Official grid of the 17 UN SDGs (2030 Agenda)** with official color palette, FWCI comparative table, and support for all 4 levels: National (all Mexico), Institutional (by ROR or acronym), Author/Researcher (by OpenAlex ID or name), and Thematic.
- `timeseries`: For annual time series with dual FWCI line and publications with a benchmark at 1.00.
- `oa-donut`: For donut charts showing Open Access route shares and APC expenditure in USD.
- `dossier-works`: For publication catalogs with international co-authorship breakdown.
- `network`: For interactive spring-layout scientific collaboration networks.
- `collaborating-countries`: For interactive choropleth world maps of international collaborating countries (Plotly.js).
- `scientific-vocabulary`: For scientific vocabulary and interactive word clouds with live search and frequency charts.
- `coauthra-network`: For dynamic interactive co-authorship networks with CoAuthra (via ORCID or OpenAlex ID).
- `quadrant-matrix`: Strategic 4-quadrant matrix (Leadership vs. FWCI Impact).
- `geopolitical-sankey`: Geopolitical collaboration flow diagram by regional blocs.
- `multidimensional-radar`: Multi-dimensional radar chart of scientometric analytical profiles.
- `topic-dynamics`: Temporal bubble trajectory and acceleration of thematic research fronts.

**Example for Bar Chart of Institutions or Authors:**
```bash
python scripts/openalex_visualizer_cli.py \
  --input ./data/top_instituciones_litio.json \
  --type top-ranking \
  --title "Leading Institutions in Lithium Research in Mexico" \
  --lang en \
  --output ./reports/ranking_instituciones_litio.html \
  --png ./reports/ranking_instituciones_litio.png
```

**Example for Research Line Sunburst:**

python scripts/openalex_visualizer_cli.py \

## Mandatory Rules for the Agent (LLM)

1. **GOLDEN LOCATION RULE (SOVEREIGN WORKSPACE):**
   - **NEVER save output artifacts (`--output`, `--png`) in `/tmp/`.**
   - The right-pane viewer and file explorer in OpenHands **can only read files inside the project's current working directory**. If you save in `/tmp/`, the viewer will throw a `404 Not Found` error.
   - Create a `./reports/` or `./data/` subdirectory inside the current workspace and always save your files there (e.g., `./reports/sunburst.html`, `./reports/tarjeta.png`).

2. **Preferred Use of Official CLI vs. Ad-Hoc Scripting:**
   - **Primary Route (Standard Catalog):** Always use `openalex_visualizer_cli.py` for standard catalog charts (horizontal bars, time series, OA donuts, sunburst, SDGs). It already implements the official dark visual theme, executive typography, optimized CDN, bilingual `--lang en|es` labels, and simultaneous PNG card export.
   - **Secondary Route (Ad-Hoc Custom Visualizations):** If the user requests a specialized chart type not supported by the CLI (e.g., bivariate scatter plots, radar/spider charts, violin plots, or boxplots), you are fully authorized to write and execute a custom Python script using `plotly` or `matplotlib`.
   - *Strict condition for custom scripts:* Always save both the interactive `.html` and `.png` card inside `./reports/` and use the dark theme template (`template="plotly_dark"` or `#0B0F19` background) to preserve the visual harmony of TlachIA-Hands.

3. **Execution Workflow (The Artifact Triad):**
   - **Phase 1 (Quantitative Computation):** Obtain structured data by running the appropriate analytical skill (`aggregations`, `works-search`, `pubmed-harvester`, etc.) and save the result in `./data/datos.json` or `.parquet`.
   - **Phase 2 (Artifact Generation):** Invoke `openalex_visualizer_cli.py` with `--png` (and optionally `--triad`) to produce the standalone interactive HTML dashboard, static PNG card, and structured `summary_kpis` metrics.
   - **Phase 3 (User Presentation according to the Triad):**
     1. **Level 1 (KPIs & Reasoning):** Write the quantitative analytical summary in natural language from the `summary_kpis` block.
     2. **Level 2 (PNG Card in Chat):** Embed the static PNG card directly in the chat for immediate preview: `![Chart](reports/tarjeta.png)`.
     3. **Level 3 (Standalone Interactive Dashboard):** Provide the clickable link to the standalone HTML `[Open Interactive Dashboard](reports/artefacto.html)` or the native tag `<agent-embed src="file:///reports/artefacto.html"></agent-embed>`. Artifacts must be completely portable, without forced iframe dependencies on remote servers.

## Common Mistakes and Anti-Patterns (Avoid Frequent Errors)

- ❌ **Anti-pattern 1: Recycling files from previous sessions in foreign folders (`../<hash>/`)**  
  Attempting to link an `.html` or `.png` generated in a previous session or parent directory. Causes black screens and 404 errors in the Canvas viewer.  
  **Solution:** Strictly follow the two-phase workflow by generating fresh data in `./data/` and rendering in `./reports/`.
- ❌ **Anti-pattern 2: Saving artifacts in `/tmp/` outside the workspace**  
  The platform's Canvas viewer can only serve files inside the current working tree.  
  **Solution:** Always save in `./reports/` or `./data/`.
- ❌ **Anti-pattern 3: Omitting static PNG card generation (`--png`)**  
  Generating only the `.html` without the PNG card for quick preview in chat.  
  **Solution:** Always pass `--png ./reports/tarjeta.png` to comply with the Visual Triad.
- ❌ **Anti-pattern 4: Using white backgrounds in ad-hoc visualization scripts**  
  Generating matplotlib or plotly charts with a default white background, breaking the aesthetic harmony of the system.  
  **Solution:** Use `template="plotly_dark"` or a palette with `#0B0F19` background.
